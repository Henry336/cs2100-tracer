# Feature sweep: c-memory

Raw research output. Priority 1 = high exam value or high confusion.

## Features (14)
### [1] Memory Box-and-Arrow Tracer (pointers and variables)
- Module: L04 Pointers (with L02 variables/types)
- Sources: L04A p5-15 (address, &, %p, name/address/value table on p11, *a_ptr same as a on p12, Example #1 p13, 'double a, *b' p14-15); L04B p3-6 (TracePointers trace, IncrementPointers, segfault CommonMistake); R02 p9-12 (pointer boxes, arrows, aliasing/dangling); T01 Q6 (Answers p6); L02A p22-26 (uninitialised = garbage, sizeof table); AY21/22 S1 Q2-Q3
- Inputs: A preset, or a short C snippet in a supported subset: int/float/double/char scalars, pointer declarations (including mixed 'double a, *b;'), &, unary *, =, compound ops (+=, -=, *=), pre/post ++/--, if/while/for, printf with %d %f %c %p. Controls: Step, Step back, Run to cursor, Reset. Toggles: show addresses vs arrows only, randomise base address, pointer size 4 (default) or 8.
- Shows: For each line, a memory table in the slide's own format (name | address | value, L04A p11) plus a box diagram. Pointer boxes get their own colour (the slides call them 'blue boxes') and an arrow to the pointee. The current line is highlighted and the written cell flashes. Old values stay struck through, the way the L04B p4 picture overwrites 15 to 120, 121, 122, 123. A statement like '*p1 *= a' is shown as two hops: read p1, follow the arrow, read and write b. Uninitialised cells show '?'. Dereferencing an uninitialised pointer stops with a red 'Segmentation fault' banner on the dangling arrow (L04B p6). An alias badge appears when two pointers reach the same box (p2 and p3 in L04B; R02 p12). A console pane collects printf output.
- Aha: *p is not a copy. It is the variable itself, reached by following an arrow. Write through p2 and *p3 changes at once, because both arrows land on c. In a declaration '*' means 'is a pointer'; in an expression it means 'follow the arrow'.
- Verify use: Before running, the user types the printf lines they expect (or the final values). The tool diffs them line by line and jumps to the first step where the trace disagrees, for example forgetting that b was already 120 before the loop. Covers T01 Q6, the L04B trace, L04A Example #1 and MCQs like AY21/22 S1 Q2/Q3.
- Conventions: Sizes: int 4, float 4, char 1, double 8 (L02A p24-26; L04B p5 'Recall Lect#2a'). Pointers default to 32-bit: the slides print 8-hex-digit addresses like ffbff7dc (L04A p7) and midterm AY25/26 Q12 states 32-bit pointers. Offer a 64-bit toggle. %p prints hex and the address 'varies from run to run' (L04A p7). Uninitialised locals are garbage, not 0 (L02A p22). 'double b = &a;' is illegal (L04A p15). ANSI C has no bool: 0 is false, nonzero is true, and relational results print as 1 or 0 (L02C p6-7). Diagram vocabulary: draw an arrow when the address is immaterial (R02 p10).

### [1] Call-Stack Frames: pass-by-value vs pass-by-address
- Module: L04 Functions (plus L05 array and struct parameters)
- Sources: L04D p3-15 (actual vs formal parameters p3, activation record p4, scope error p5, PassByValue p6, SwapIncorrect p7-9, SwapCorrect p10-11, Examples 1-4 p12-15); L04C p6-11 (prototypes, implicit int error); R02 p16-17, p44 ('Function calls', diagram only); L05A p11-15 (array parameters); L05D p2-9 (struct parameters); T01 Q5 (reverseArray, iterative and recursive); AY23/24 S2 Q2 (mystery); AY21/22 S1 Q2
- Inputs: A preset or a snippet with up to about three functions, one of which may be recursive. Controls: step into, step over, step out. Toggle: show addresses.
- Shows: The stack as stacked frames labelled 'In main():' and 'In swap():' (L04D p9-11). On a call, a new activation record slides in. Each formal parameter is filled by an animated COPY from the caller's box (L04D p3 shows 3.2 and 2.0 arriving in x and y). Pointer parameters draw arrows that cross the frame wall back into main's boxes. On return the frame greys out and pops, its locals vanish (automatic variables, L04D p4), and the return value travels back. An array argument appears as an arrow to the caller's array with no copy, and its size arrives as a separate copied int (L05A p11). A struct argument appears as a full duplicate (L05D p6). Recursion (reverseArrayRec) stacks frames with left/right values while the swaps act on the one shared array.
- Aha: A function only ever receives copies. swap(a, b) swaps the copies. swap(&a, &b) copies the ADDRESSES, so the callee can reach back across the frame wall. Even swapping two pointer parameters inside the callee (AY23/24 S2 mystery) leaves the caller untouched, because those pointers were copies too.
- Verify use: Predict-then-run for L04D p6 and p12-13 outputs, both swap versions, AY23/24 S2 Q2 (expect 100) and T01 Q5. The frame view also answers 'can f see this variable?' questions (L04D p5: a is local to main).
- Conventions: C passes by value only (L04D p3, p8). Formal parameters and locals are local and exist only during the call (L04D p4). Prototype before main with return type, name and parameter types; names are optional (L04C p10). A missing prototype makes the compiler assume int, then report 'conflicting types' (L04C p11). 'int arr[]' is the same as 'int *arr', and any size inside [] is ignored (L05A p12-13). In the slides, later-declared locals sit at lower addresses (L04D p15: a=ffbff78c, b=ffbff788, c=ffbff784).

### [1] Expression and Precedence Stepper (side effects, ++/--, *, ->, ?:, casts)
- Module: L02 operators plus L04/L05 pointer expressions
- Sources: L02B p7-13 (lvalues, associativity, truncation, mixed types, casts, C vs Python %); L02C p9-18 (precedence table, boolean example, short circuit); R01 p17 (an assignment is an expression); L05D p10 ((*p).name vs *p.name); AY25/26 S1 Q10 ('++(*pp) <= *qq--'); Midterm AY25/26 Q9-Q11; AY24/25 S1 Q8 ('x>0?0:1'); student cheat sheet in Exam Prep/Finals Notes p1 (*ptr++ vs (*ptr)++ vs ++*ptr)
- Inputs: One C expression or statement plus current variable values. The values can be typed in or taken from the memory tracer's current state.
- Shows: A parse tree built from the course precedence table, banded by precedence level with associativity marked. One click evaluates one node bottom-up, showing its value. Side effects are drawn: a post-increment shows as 'pending' until the statement ends, then applies. A short-circuited subtree greys out as 'not evaluated'. Pointer nodes show both the address and the pointee. Integer nodes show truncation, e.g. 10/4 gives 2 before any float conversion. A side panel lists equivalent rewrites: *p++ is *(p++), p->m is (*p).m, a[i] is *(a+i), and c?x:y becomes an if/else.
- Aha: Postfix ++/-- and [] . -> bind tighter than unary *. So *qq-- moves the pointer, not the value, and *p.name means *(p.name). '&&' binds tighter than '||', so a > b || b > c && a == b is 1. In 12/5 the division is integer and gives 2 before it becomes a double (L04D p3 shows y = 2.0).
- Verify use: Checks L02C p10-17 (x=1, y=0, z=1), the L02B p12 cast table, AY25/26 Q10 (prints 51), midterm Q11 (1 100 3 4) and AY24/25 Q8 (2 3). The user enters an expected value, and the tool highlights the first node they evaluated differently.
- Conventions: Precedence from high to low (L02C p9): () [] . -> expr++ expr--; unary * & + - ! ~ ++expr --expr (cast) sizeof; * / %; + -; < > <= >=; == !=; &&; ||; ?:; assignment. Unary operators, ?: and assignment associate right to left; the rest left to right. Integer results truncate: n = 9*0.5 stores 4 (L02B p9). C % takes the sign of the dividend: -10%4 = -2 (L02B p13). Cascaded assignment runs right to left (L02B p3-8; R01 p17). ?: is 'not covered in lecture' (T02 Answers p3 tutor note) yet appears in AY24/25 Q8 and midterm Q8.

### [1] Array Address Calculator and Linear Memory Strip (1D, 2D, nD row-major)
- Module: L05 arrays plus R02 multidimensional arrays
- Sources: L05A p5-15; R02 p20-21, p24-26 (linearisation and the general address formula); Exam Prep 'Recitation and Tutorial Extras' p6-7; AY19/20 S2 Q7 (row-major image arrays; part f asks about column-major); Lab 2 (sizeof array / sizeof element); L04B p5
- Inputs: Element type (char/int/float/double, a struct of known size, or a custom size S), dimensions D1..Dn, base address A0 in hex, and an index tuple. Cells can also be clicked in the grid view. Toggle row-major / column-major. Optional loop order (i outer or j outer) to animate a traversal.
- Shows: Two linked views: the logical grid (2D/3D tabs) and the 1D byte strip with addresses. Picking a[i1]..[in] animates the Horner-style evaluation ((i1×D2 + i2)×D3 + ...), then the element offset ×S, then +A0, with each term coloured to match its dimension. Shows that a[i] equals *(a+i) and &a[i] = a + i×S. The array name is drawn as a locked arrow to a[0] that cannot be reassigned (L05A p9). Traversal mode animates the address sequence and marks the stride (S versus D2×S), so contiguous and strided access look different; this sets up the cache lectures. A sizeof panel compares sizeof(arr) in the declaring scope with sizeof inside a function, where the array has decayed to a pointer.
- Aha: A 2D array is one long strip. The row index is worth a whole row of D2 elements. Row-major means the LAST index changes fastest, so a[r][c+1] is next door while a[r+1][c] is D2×S bytes away.
- Verify use: Type an address question (e.g. int a[3][4], &a[2][1]) and get A0+36 with the working shown. Check array-base inputs for cache questions (AY19/20 Q7: A at 0x0040CCC0, A[i] at base + 4i). Confirm MIPS offsets (index×4 for int, ×1 for char) before writing lw/sw.
- Conventions: Indices start at 0; elements are contiguous and all the same type (L05A p5). Consecutive int elements are 4 bytes apart (L05A p8: a = &a[0] = ffbff724, &a[1] = ffbff728). General formula: A0 + S×(i1×D2×…×Dn + i2×D3×…×Dn + … + in) (R02 p26; the text extract is garbled, so use the reconstruction in the R02 guide and the Extras). 'Row major' and 'column major' are named on R02 p25 (picture only) and are absent from L05. The array name is a constant pointer, so 'dest = source' is illegal (L05A p9; R02 p21). Initialisers: missing values become 0, 'int b[] = {1,2,3}' has size 3, excess values give a warning, and '{...}' only works at declaration (L05A p7).

### [1] Struct Builder: layout, copy semantics, ->, arrays of structs, unions
- Module: L05 structures plus R02
- Sources: L05C p2-15 (groups, typedef, tags, initialising, '.', assignment p12, returning structs p13-15); L05D p2-11 (pass by value p2-7, pass by address p8-9, arrow p10-11, array of structs p4); R02 p28-35 (nested init p28, pointer member p29, pointers to structs p30, copy and return p31, unions p32, typedef p34, enum p35); AY21/22 S2 Q3; AY17/18 S2 Q1a; AY23/24 S2 Q1; Midterm AY25/26 Q7; R02 quiz answers p60-62
- Inputs: Define a struct or typedef with members of int/float/double/char, char arrays, int arrays, pointers or nested structs. Declare variables with initialisers. Then run operations: s2 = s1, pass by value, pass by pointer, p->m and (*p).m, arrays of structs, return a struct. A union toggle is included.
- Shows: Each struct is a labelled group box with member sub-boxes in declaration order (L05C p3, p12). Assignment animates a member-by-member copy (L05C p12 'Before/After'). Passing by value clones the whole box into the callee's frame (L05D p6). Array members are cloned too, but a pointer member clones only its arrow, so both copies point at the same int; this is the AY21/22 S2 Q3 twist (x[1] vs *y). -> is animated as 'follow the arrow, then pick the member'. Typing *p.name gives a red parse error with the precedence reason (L05D p10). Union mode overlays all members on the same bytes, with size = the largest member (R02 p32). A 'real compiler padding' overlay is off by default and labelled non-examinable.
- Aha: Structs behave like big ints: = copies everything, and passing by value copies everything, arrays inside included. A pointer member is copied as an address, so the copy and the original share the pointee. Arrays are the odd one out: no =, and they are passed as an address.
- Verify use: Checks AY17/18 Q1a ('11 A' then '33 f'), AY21/22 S2 Q3 (D), AY23/24 S2 Q1 (B), the L05D p5 and p8 outputs, the R02 quiz results on p60 and p62, and midterm Q7 initialiser validity.
- Conventions: The typedef semicolon is required (L05C p4). A type is not a variable and gets no memory (L05C p5). Tag vs typedef; an anonymous struct variable is legal (L05C p7). Initialise like arrays, with nested braces for nested structs (L05C p8; R02 p28). Access with '.', and scanf with &s.member (L05C p9-11). Struct assignment is legal, array assignment is not, 'because the compiler knows the size' (R02 p31). p->m is the same as (*p).m, and '.' binds tighter than '*' (L05D p10). Passing an array of structs lets the callee modify the elements (L05D p7 note). Padding and alignment are never taught in L05/R02, and no slide computes sizeof(struct), so do not present padding as course content.

### [2] String / char-array Inspector
- Module: L05 strings
- Sources: L05B p2-13 (char arrays, '\0', fgets/scanf/puts, RemoveVowels, string functions, missing terminator); R02 p22; L03B p3-5 (ASCII, 'A' = 65); AY21/22 S2 Q7 (what equals strlen(s)); Midterm AY25/26 Q7 (char s[3] initialised with "abc"); Lab 2 lab2c (modifying through a pointer segfaults, incrementing an array is an error); student cheat sheet in Exam Prep/Finals Notes p1 (string literals are read-only)
- Inputs: Declare a buffer (char str[N]) and fill it with a literal, a brace list or per-index assignments. Feed simulated input lines to scanf("%s") or fgets(str, size, stdin). Run strlen, strcpy, strncpy, strcmp, printf %s or puts. Toggle: show ASCII codes.
- Shows: A row of byte cells, each with index, address, glyph and ASCII code. '\0' cells are highlighted and unknown cells show '?' (L05B p4, p6). Each function animates a cursor walking the cells. strlen counts until '\0'. printf %s prints until '\0'; if there is none, the cursor runs past the end into neighbouring memory shown as garbage (WithoutNullChar, L05B p13). fgets stores the '\n', then the strip-newline step runs (L05B p6). scanf stops at whitespace (L05B p7). A too-long strcpy spills red into the next variable (L05B p11, 'A very long name'). strcmp shows the pairwise ASCII comparisons and the sign of the result. A toggle compares char str[] = "..." (mutable array) with char *s = "..." (pointer to a read-only literal); writing s[0] in the pointer case shows the segfault.
- Aha: 'String' is a convention, not a type: chars followed by a '\0'. Every string function is a loop hunting for that zero, so strlen(s) equals (address of the first '\0') − s.
- Verify use: Checks strlen questions (AY21/22 S2 Q7 options A and D), buffer sizing (N chars need N+1), fgets vs scanf on 'My book', and RemoveVowels output. Also checks whether a char[3] can hold "abc" as a proper string (midterm Q7). The user predicts the printed text and the length.
- Conventions: '\0' has ASCII value 0 (L05B p3). "apple" gets its '\0' automatically (L05B p4). fgets reads size−1 chars and keeps the '\n' (L05B p5-6). puts adds a newline (L05B p7). Avoid gets (L05B p5). 'name = "Matthew";' does not work; use strcpy (L05B p11). strcmp returns negative, 0 or positive by ASCII (L05B p10). A 100-char buffer is char str[101] (L05B p9). char and int are interchangeable for 0-127 (L03B p3-5). 'a' − 'A' = 32 is used in AY17/18 Q1a.

### [2] Endianness and Byte-Order Viewer
- Module: R02 memory (plus L10 ISA)
- Sources: R02 p6-8 (memory as an array of bytes; picture labels x86 little-endian and 'Our MIPS' big-endian); L10 p17-18 (0xDEADBEEF stored DE AD BE EF vs EF BE AD DE; 'endian-ness of MIPS is implementation specific'; the online MIPS interpreter is little-endian); AY21/22 S1 Q7 (bytes 0x43 0x61 0x74 0x73 at 0x3E8); Midterm AY25/26 Q18 (big-endian sender, little-endian receiver, odd parity); student cheat sheets in Exam Prep (char arrays are unaffected)
- Inputs: A 32-bit value in hex, or 4 bytes typed per address. Start address. Endianness toggle. Which type to view: int, unsigned, char[4] or float bits. A 'send to the other-endian machine' button.
- Shows: The word box split into Byte 3..Byte 0 with bit ranges 31-24 down to 7-0, as in the R02 p8 picture, next to a memory column x, x+1, x+2, x+3. Toggling endianness animates the bytes moving into their address slots. Reading back: char[4] reads in increasing address order and never changes, while int reads according to the chosen endianness. Both readings sit side by side with decimal values. 'Send' mode byte-swaps and shows that the count of 1 bits stays the same while the numeric value changes.
- Aha: Endianness only reorders the BYTES of a multi-byte value. Bits inside a byte, the order of separate chars, and the order of separate words do not move. The same 4 bytes are "Cats" as chars on either machine, but the integer is 1130460275 on a big-endian machine and 1937006915 on a little-endian one.
- Verify use: Checks AY21/22 S1 Q7: option C is false (the big-endian value is 1130460275, not 1130460273) and D is true. Checks midterm Q18: the three words have 15, 13 and 21 one-bits, all odd, so all pass and the answer is D. Also helps with lb/lw byte-picking reasoning in MIPS.
- Conventions: Big-endian puts the most significant byte at the lowest address; little-endian puts the least significant byte there (L10 p17). R02 p8 labels Intel x86 little-endian and 'Our MIPS' big-endian. L10 p17 says MIPS endianness is implementation specific, and L10 p18 says the online interpreter is little-endian, so the tool must always state which endianness it assumes. Bit 31 (MSB) is drawn on the left (T02 Answers p4). Memory is byte-addressed (R02 p6).

### [2] Scope and Lifetime Lens (lexical scoping, shadowing, static)
- Module: L04D scoping plus R02
- Sources: L04D p4-5, p16-18 (scoping example with printed lines 1-6; static); R02 p4 (shadowed i prints 1, 2, 3, 2, 4); R02 p42-43 (const, #define vs a variable, static local and file-scope static); L02A p27-29 (declaration vs definition, extern); R01 p16
- Inputs: A snippet with globals, nested blocks, helper functions and static locals. Step controls, and a button to call a function repeatedly.
- Shows: Nested coloured rectangles for the global scope, each function scope and each {} block. When a name is used, an arrow searches outward from the current block to the nearest declaration. Shadowed outer variables dim but keep their values. A called function resolves names from where ITS text is written, so foo sees the global x, not main's. A lifetime strip shows automatic variables appearing and disappearing with frames. Static locals live in a separate static area and keep their value between calls (counter demo). A file-scope static gets a padlock marked 'not visible outside prog.c'.
- Aha: C picks which x you mean by where the code is WRITTEN, not by who called it. That is why foo() prints −1 even though main's x is 30 at the time.
- Verify use: Checks L04D p17 (10, 20, 10, 30, −1, 30), R02 p4 (1, 2, 3, 2, 4), and 'what does the third call print' questions about static counters.
- Conventions: C uses lexical (static) scoping: one global scope, nested local scopes, and every {} block opens a new one (L04D p16; R02 p4). A static global has file scope; a static local has an extended lifetime (L04D p18; R02 p43). Automatic variables exist only during the call (L04D p4).

### [3] Same Bits, Different Type (reinterpret and union lens)
- Module: R01 data representation plus R02 unions

## Misconceptions and traps (surface as callouts)
- Thinking that changing a function's parameter changes the caller's variable. C passes copies, so swap(a, b) leaves main's a=2, b=3 unchanged. (L04D p6-9; R02 p16)
- Thinking that swapping two POINTER parameters inside a function swaps the caller's data. The pointers are copies too: mystery() changes nothing and main prints 100. (AY23/24 S2 Final Q2 (key: A))
- Treating arrays like structs, or the other way round. Arrays cannot be assigned ('dest = source' is illegal) and are passed as an address, so the callee can modify them. Structs CAN be assigned and returned, and are passed by value, so the callee gets a copy. (L05A p9, p14-15; L05C p12; L05D p5-7; R02 p31)
- Assuming a struct copy is deep. An array member is copied, but a pointer member copies only the address, so writes through it still reach the caller's data (x[1] vs *y). (AY21/22 S2 Final Q3)
- Writing *p.name for (*p).name. '.' binds tighter than '*', so *p.name means *(p.name). Use p->name. (L05D p10)
- Reading 'double a, *b;' or 'int *a, b;' as declaring two pointers. The '*' belongs to each declarator: b (or a) is the pointer, the other is a plain variable. Also, 'double b = &a;' is illegal. (L04A p14-15)
- '*' means the same thing everywhere. In a declaration it means 'is a pointer'; in an expression it means dereference. (L04A p9, p12; guides/L04 traps)
- Thinking p++ adds 1 to the address. It adds sizeof(pointee): +4 for int/float, +1 for char, +8 for double, and ap += 3 adds 12. (L04B p5; R02 p14)
- Declaring a pointer and writing through it without pointing it at storage: 'int *n; *n = 123;' gives a segmentation fault. Declaring a pointer is not allocating what it points to. (L04B p6; R02 p36)
- Using a pointer after free() (a dangling pointer), e.g. *ptr = 2 after a callee freed ptr. (R02 p12, p40)
- Assuming uninitialised local variables start at 0. They hold garbage. (Static and global objects are zeroed, according to the student cheat sheet.) (L02A p22; Exam Prep/Finals Notes p1 (student cheat sheet))
- Forgetting room for '\0'. Without it, strlen and printf %s run past the end; L05B p13 shows 'Length = 8' and garbage for a 5-letter word. A 100-char buffer needs char[101]. (L05B p9, p12-13; R02 p22)
- Assigning strings with '=' ('name = "Matthew";'). Use strcpy, and make sure the destination is big enough: strcpy of 'A very long name' into char[10] overflows. (L05B p11)
- Expecting fgets to drop the newline, or scanf("%s") to read a whole line. fgets keeps '\n' (strip it manually); scanf stops at whitespace, so 'My book' gives 'My'. puts adds its own newline. (L05B p5-7)
- Writing the array size in a parameter and expecting it to mean something. 'int arr[8]' in a parameter list is ignored, so pass the size separately. sizeof(arr) inside the callee gives the size of a POINTER, not the array, and not the first element either (the filled-in Lab 2 sheet says 'size of the first element', which is wrong; on 64-bit it is 8 bytes). (L05A p11-13; Lab 2 Q10; Exam Prep/Finals Notes p1 (student cheat sheet))
- Using an initialiser list after declaration ('f[5] = {8, 23, ...};' is a compile error), or not knowing that missing initialiser values become 0 ('int c[5] = {17, 3, 10}' gives c[3] = c[4] = 0). (L05A p7)
- Expecting integer division to keep the fraction. 10/4 is 2, 'float p = 10/4' is 2.0, 'int n = 9*0.5' stores 4, and in the slide's call sqrt_sum_square(3.2, 12/5) the second argument arrives as 2.0. (L02B p9, p12; L04D p3)
- Assuming C % works like Python %. In C, -10 % 4 = -2 (a remainder with the dividend's sign); in Python it is 2. (L02B p13)
- Assuming || and && have equal precedence. && binds tighter, so with a=4, b=-2, c=0, 'a > b || b > c && a == b' is 1, while the parenthesised version '(a > b || b > c) && a == b' is 0. (L02C p10-17)
- Trusting indentation. An unbraced if/else body is one statement, so the printf after it always runs (AY24/25 Q8 prints '2 3'). ?: is 'not covered in lecture' but is examined. (AY24/25 S1 Final Q8; T02 Answers p3 tutor note; Midterm AY25/26 Q8)
- Thinking *q++ increments the value. Postfix ++/-- bind tighter than unary *, so '**q++ = 100' writes through the old q and then moves q, and '*qq--' reads p[99] and then steps qq back. (L02C p9 (precedence table); Midterm AY25/26 Q11; AY25/26 S1 Final Q10)
- Thinking break leaves every enclosing loop. It only leaves the innermost loop (or switch), and continue only skips the rest of the innermost loop's current iteration. (L02C p26-30)
- Assuming a called function sees its caller's local variables. C is lexically scoped: foo() sees the global x = −1, not main's x = 30, and f() cannot use main's local a. (L04D p5, p16-17; R02 p4)
- Thinking a typedef or struct definition allocates memory, or forgetting the semicolon after the closing brace. A type is not a variable. (L05C p4-5, p7)
- Omitting the function prototype. The compiler assumes the function returns int, then reports 'conflicting types' when it reaches the real definition. (L04C p10-11)
- Thinking endianness reorders the characters of a string or the bits within a byte. It only reorders the bytes of a multi-byte value. Also, 'MIPS is big-endian' is not absolute: L10 calls it implementation-specific, and the online interpreter is little-endian. (L10 p17-18; R02 p8; Exam Prep cheat sheets (endianness section))
- Dereferencing a void * directly. It must be cast to the correct type first. (R02 p18)
- The slide code for SwapCorrect declares a, b but uses var1, var2 in scanf and printf, so it would not compile as printed. Treat it as a slide typo; the swap logic is what matters. (L04D p11; R02 p17)
