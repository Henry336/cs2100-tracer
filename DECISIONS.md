# Decisions

Judgement calls made while building the tracer unattended (21-22 Nov 2026), with the reason for each. The first sections are the ones that change what a student sees. The appendix lists every decision the module agents recorded.

## How the build was run

| Decision | Reason |
|---|---|
| Two module lanes, each strictly one agent at a time (lane 1: mips, cache, pipeline, datapath, c-memory; lane 2: boolean, msi, sequential). | A 16-agent parallel run crashed the 7.2 GB laptop. Two agents at once stayed under about 6.5 GB. |
| Each module went through six stages: core engine, course-fidelity verifier, edge-case verifier, fix, UI, UI review. | The verifiers try to break the engine against the slides and keys before any UI is built on it. |
| Subagents ran at high effort, not xhigh, after the first 12 calls. | Requested by the student. The first 12 results were already cached, so rerunning them would have redone finished work. |
| No dev server while agents ran; agents checked layouts with server-side renders. One browser pass by the integrator afterwards. | RAM. The browser pass found one phone-width overflow (fixed) and no console errors. |
| Deployed before the final review, then again after its fixes. | Everything was already tested, built and browser-checked, so the site was usable sooner. |

## Interface decisions

| Decision | Reason |
|---|---|
| Hash router; every input lives in the URL. | Any view is a shareable link, and GitHub Pages needs no 404 rewrite. |
| Signal colours have one fixed meaning everywhere (path, data, control, forward, stall, flush, hit, miss, dirty, don't care), always with a label or pattern too. | One visual language across modules, readable without colour. |
| Export PDF = print stylesheet + the browser's Save as PDF, always in the light theme. | No dependency, works offline, text stays selectable. |
| Focus mode on the datapath, pipelined datapath, datapath timing, C memory, gate circuits, MSI and sequential diagrams ("Show only what this instruction uses", "what this step changes", "what is stable at this time"): unused parts are hidden, the rest keep their positions. Not on the latch circuit or the control PLA. | Requested; hiding (not fading) makes the used path obvious. The latch uses every gate in every settling round, so there is nothing to hide; the PLA already shows firing terms. |
| Pipeline Show switch: Actual / Ideal / Compare. Compare splits the gap into data stalls, control stalls and flushed fetches using the engine's own totals. | Requested after the pipeline agents had finished, so the integrator built it; a test checks the parts add up. |
| Answer checkers hide the answer until the student submits. | Study rule: no answer before an attempt. |
| Shared layout fixes applied globally (wrapping panel heads and segmented controls, workspace head min-width, capped preset width, don't-care styles). | Four modules hit the same 375 px overflow and patched it locally. |
| No slide or past-paper text in the repo. Fixtures are numbers and short instruction sequences with a source reference. | Copyright. |

## Appendix: every decision the module agents recorded

Format: `[stage:module] decision || reason`.

- [core:mips] Expand ulw into lbu + sll + or using $at (10 real instructions). Reject ulw when the destination is the base register or $at. || L07 p12 says ulw becomes byte loads plus other operations. lwl and lwr appear on that slide only by name and their behaviour is not taught. lbu avoids sign bits leaking into the OR. Big-endian byte order follows R02 p8.
- [core:mips] run starts at the `main` label when it exists, otherwise at the first instruction. || In QtSpim the startup code calls main (Lab 3 SPIM-assembler p1). Programs that start with main behave exactly as before.
- [core:mips] Reaching the address just past the last instruction ends normally. Any other address with no instruction is halted: 'error'. || This keeps end-of-program labels like `exit:` working, while a wild branch or jump fails as QtSpim does (Lab 3 p7). `jr $ra` with $ra never set also fails, because 0 is not end+4.
- [core:mips] The default text base stays 0x00400000. Only the AY24/25 Q18 preset uses 0x00400024. || Lab 3 p5 (user code at 0x00400024) and Lab 5 (code at 0x00400000) disagree, as the spec ambiguity notes. The Q18 key's addresses only work with 0x00400024.
- [core:mips] Add addu, addiu and sltu as green-card, non-lecture instructions. Skip lh and sh. || The spec asks for the T02 p1 extras. lh and sh would need a 2-byte memory access size, but the shared MemAccess contract only allows 1 or 4.
- [core:mips] Lookup tables (OP_BY_NAME, labels, hints) are objects with no prototype, built by an exported dict() helper in isa.ts. || Without this, user text such as 'constructor' or '__proto__' crashed the assembler or gave wrong label results, and parsers must never throw on user input.
- [core:mips] Zero bytes from program.data are not stored in run memory. Missing bytes already read as 0. || Copying a 64 KB .space buffer two or three times per run took about 150 ms on this machine. Reads are unchanged; the UI should use program.data to know which addresses belong to the data segment.
- [core:mips] Kept the verifier test files and changed one stale assertion: `.half` is now a supported directive, so the unknown-directive check uses `.dword`. || The verifier tests describe course behaviour, and the old assertion contradicted the new `.half` support.
- [fix:mips] A number after j or jal is the 26-bit target field by default. AssembleOptions.jumpOperand: 'address' gives QtSpim's byte-address reading. || The rendered L08 p8 slide shows 'j 2500' going to 10000 and 'jal 2500' setting $ra = PC + 4 before going to 10000. R04 p44 Q7 agrees. T03 Q2's decoded answers and QtSpim use the address form, so the course is ambiguous and architecture.md asks for an option with a default. The error for a field over 26 bits still mentions '256 MB', which the existing assembler test needs.
- [fix:mips] Fixed a wrong expected value in a verifier test: 'ori $s3, $s0, -1' is 0x3613FFFF, not 0x3612FFFF. || $s3 is register 19, so rt = 19 gives 0x3613FFFF. The verifier reused the rt of the andi line ($s2 = 18). The andi word, 0x3212FFFF, and both run results were already correct.
- [fix:mips] andi, ori and xori accept -32768 to 0xFFFF and keep the low 16 bits. lui still accepts only 0 to 0xFFFF. || AY24/25 S1 Q11, an official paper, gives 'andi/ori $z, $x, -1' as real MIPS. Logical immediates are raw 16-bit patterns that get zero-extended (L06 p46, L08 p19). Nothing in the course writes lui with a negative value. The error message keeps '0 to 0xFFFF' because the T02 D2(d) test checks it.
- [fix:mips] Byte order is set once on assemble (AssembleOptions.endian, default 'big') and stored on Program.endian, which run reads. RunResult.endian records it so memoryAt replays writes correctly. || The spec (mips-isa.md lines 9, 103, 267) asks for an explicit byte-order toggle. Setting it in one place stops the assembler's .word layout and the run's lw/sw from disagreeing. R02 p8 calls our MIPS big-endian, so that is the default; L10 p18 and QtSpim are little-endian.
- [fix:mips] Added RunResult.statements, which counts a pseudo-instruction such as ulw once. frames.length still counts real instructions. || The official answer to L07 p38 Ex5 is 42 executed instructions, counting each ulw as one. The ulw expansion into 10 real instructions makes 132 frames. Exposing both lets the UI show the course's number next to the real count.
- [fix:mips] read_int (syscall 5) reads RunInit.input, one integer per line, and ignores text after the number. || Lab 4 p1-2 and Lab 5 p4 use read_int, and Lab 4 p2 says it reads a whole line and ignores the characters after the number. A missing line or a line without a number gives a plain run error instead of a crash.
- [fix:mips] lh (21hex, standard MIPS), lhu (25hex, green card) and sh (29hex, green card) are marked lecture: false, and halfwords must be at even addresses. || L07 p12 names lh and sh, and T02 p1 and the spec's Gaps section say to support them but mark them non-lecture. The course does not teach halfword alignment, so the error message cites QtSpim's behaviour instead of a lecture.
- [fix:mips] decode returns an error for a word whose fixed-zero fields are set: shamt for arithmetic, rs for shifts and lui, rt/rd/shamt for jr, and bits 25-6 for syscall. || L08 p15 says shamt is always 0 for arithmetic and rs is always 0 for shifts, and the AY25/26 Q6 key encodes lui with rs = 0. Such a word is not the encoding of any text decode could print.
- [fix:mips] A textBase option that is not a multiple of 4 gives an AsmError with line 0. AsmError.line documents 0 as an option error. || The option has no source line. Rejecting it is more honest than silently aligning it (L08 p23).
- [fix:mips] Left la and li expanding without $at (lui $rd / ori $rd, $rd). || L06 p44 itself shows lui $t0 / ori $t0, $t0, and the course never says which form la uses. The verifier marked this low priority, and instruction counts already match the Lab 5 and AY24/25 Q18 layouts.
- [ui:mips] One step shows the state after that instruction has run. There is no separate frame for the state before the first instruction. || The engine's frames hold the registers after each instruction. This keeps one step as one instruction and matches the instruction count shown on the Transport.
- [ui:mips] Each tab renders its own Workspace. The Tabs sit in the intro area under the title. || The inspector and Transport differ per tab. The Transport, and its arrow and space keys, should only be active on the Run tab.
- [ui:mips] Tables that hold Why values (registers, memory, opcode results) are plain grids or tables inside the panel, not DataTable. || DataTable's overflow-x wrapper clips or scrolls the Why popover. DataTable is used only for the trace and the instruction list, which have no Why values.
- [ui:mips] Signal colours: path is the current line, a changed register and the PC flow. data is memory read this step and constant bits. dirty is memory written. control is opcode and funct, and opcodes given to a type. dontcare is unused opcode patterns. Each view has a Legend. || These keep the fixed meanings in architecture.md. Fields fixed at 0 are dashed and labelled in text rather than given a signal colour.
- [ui:mips] The Run tab stops after 2000 instructions and says so. || Transport draws one tick per frame, and the machine has little RAM. All course presets finish in well under 2000.
- [ui:mips] Initial registers and memory are entered as text, parsed by a new engine module (core/mips/init.ts) that has its own tests. || Text keeps them shareable in the URL and lets errors show line numbers. The parsers live in core because they take user input.
- [ui:mips] Course ambiguities are explicit toggles: byte order (default big, R02 p8), jal PC+4 or PC+8 (default PC+4, L08 p8), and the meaning of a number after j (default target field, L08 p8). Each has a course callout. || This follows the architecture rule for ambiguities, and the spec asks for a visible endian toggle.
- [review:mips] Added a new 'Branch conditions' tab. The engine is core/mips/inequality.ts with INEQUALITIES and inequalityBranch. The UI has a condition picker, branch when it holds or fails, register and label fields, a value for each register, the 2 real instructions, the pseudo-instruction name, the $at value and whether the branch is taken, and a table of all four conditions built from one slt. || This is a priority-1 feature (spec features/mips-isa.md) and it was missing. Tests use L07 p29 blt (official) and T03 D1(e) bge (official), plus an exhaustive check that the branch is taken exactly when the condition holds. Presets: L07 p29, T03 D1(e), L07 p22/p30 if-skip, and the L07 p33 loop exit.

The panel diffs your word field by field, names the matching known mistake, and lists the common wrong answers for the instruction. The typed answer is kept in the URL ('eans'). || Priority-1 encoder items: 'Likely mistakes' re-encoding and the field-by-field diff of the student's hex. Tests reproduce the AY24/25 S1 Q18 key's listed mistakes, 0x1180000C (counted from PC) and 0xAE890000 (rs and rt swapped). Mistakes also cover the L08 p12 assembly-order error, a branch offset in bytes, a shift source put in rs, and a jump field with the low 2 bits kept.

Each has a Why, and a chip says which one the instruction uses. || Partial cover of the priority-1 immediate extension visualizer (L06 p33, p44, p46; L08 p19). It is small and reuses signExt16.

The logic is in core/mips/profile.ts (lineProfile, uniqueBytesRead) and is computed inside the existing simulation memo. || These are priority-1 stepper items: per-line hit counts and branch-taken counts, which answer 'how many times does bne branch' questions, and unique bytes read. Putting the logic in core keeps the UI from re-simulating and makes it testable. The test is L07 Ex5 (official): 42 statements, bne 10 runs and 9 taken, 13 unique bytes.

Encode: add $10,$7,$5 (L08 p14), addi $9,$10,-32 (R04 p38), beq $s0,$s1,4 (R04 p39), lw $v1,-100($t7) (Midterm Q13), and a j decode at 0x2100FFFC (AY18-19 Q3b, the block-edge case). Run: andi zero-extension (AY25/26 Q14) and a 32-bit constant with lui then ori against addi (L06 p44, p46).
